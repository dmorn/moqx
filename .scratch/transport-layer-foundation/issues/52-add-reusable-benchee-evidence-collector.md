# Add reusable Benchee evidence collector

## Context

`bench/moqxprobe` is becoming the place where Benchee-based caller benchmarks
compare stream, DATAGRAM, mixed, and future MOQ-shaped client implementations.
Delivery-aware runs need receiver-side evidence, but polling a target such as
`quicprobe` must not be part of the measured function.

The agreed model is:

- Benchee measures the caller implementation only;
- the measured function returns a small run receipt describing what was sent
  and how receiver evidence can be matched;
- an unmeasured post-run hook reads target evidence after the test connection
  has been closed/finalized;
- a collector records expected-vs-observed delivery evidence as sidecar data;
- benchmark timing and delivery validity remain separate.

## Design

Add a reusable Benchee integration module under the `bench/moqxprobe` Mix
project, tentatively:

`MOQXProbe.Benchee.EvidenceCollector`

The module should be a small ETS-backed helper/plugin that every
Benchee-based script can reuse. It should not be tied to the current
stream-client script.

Responsibilities:

- create and own an ETS table for the current suite/run;
- provide a run receipt shape that benchmark functions can return without
  doing target polling in the timed path;
- provide a post-run API for Benchee `after_each` or an equivalent script-level
  post hook to attach receiver evidence to that receipt;
- record expected payload counts/bytes, observed receiver counters, validity,
  target metadata, scenario name, input name, implementation name, and errors;
- flush or print sidecar evidence after the suite, without modifying Benchee's
  timing samples;
- support fake targets by reading local process counters;
- support `quicprobe` targets by reading `server_run_evidence` records from a
  file/journal/API adapter after the measured invocation has returned.

Non-goals:

- do not poll `quicprobe` inside the timed function;
- do not make receiver evidence part of Benchee timing;
- do not use `Application` env or mutable global config;
- do not reintroduce `transport-bench-v1`, `probed`, ledger, Terraform, or
  remote orchestration.

## Notes

Benchee hooks are unmeasured for ordinary benchmark functions, but their return
values are discarded. Therefore the collector must be an explicit side channel
owned by the script rather than an implicit mutation of the Benchee result.

The first consumer should be the delivery-aware stream/object profile in
`.scratch/transport-layer-foundation/issues/50-build-delivery-aware-moqxprobe-caller-clients.md`.

## Comments

### 2026-06-18 implementation

Implemented the reusable evidence layer under `bench/moqxprobe`:

- `MOQXProbe.Benchee.RunReceipt` describes a measured invocation and expected
  receiver counters without polling inside the timed path;
- `MOQXProbe.Benchee.Evidence` stores expected-vs-observed counters, validity,
  mismatches, timeout/error state, and target metadata;
- `MOQXProbe.Benchee.EvidenceCollector` owns an ETS table, stores receipts and
  post-run evidence, provides a Benchee-compatible `after_each/3` helper,
  emits JSONL sidecars with Elixir's native `JSON` wrapper, and produces
  compact summary counts;
- `MOQXProbe.Benchee.EvidenceAdapter` defines the adapter contract;
- `MOQXProbe.Benchee.Adapters.FakeTransport` reads explicit fake transport
  state/counters after the timed invocation;
- `MOQXProbe.Benchee.Adapters.Quicprobe` polls a `server_run_evidence` JSONL
  file after the timed invocation and turns matching receiver evidence into
  collector evidence.

Follow-up integration in `bench/moqxprobe/bench/stream_clients.exs` wires the
collector into the first object-stream benchmark path:

- `--evidence-output` enables evidence mode and writes the collector sidecar
  JSONL after `Benchee.run/2`;
- evidence mode requires `--benchee-parallel 1` so each measured invocation has
  an unambiguous receiver record;
- fake-target evidence is recorded through an explicit ETS-backed fake
  transport counter store and read by
  `MOQXProbe.Benchee.Adapters.FakeTransport`;
- quicprobe-target evidence records the latest server `run_sequence` before
  the timed invocation, then matches the first `server_run_evidence` record
  after that cursor;
- for quicprobe, connection finalization happens in the unmeasured post hook
  with a target-aware close grace (`--evidence-close-grace-ms`, default 25 ms)
  before polling receiver evidence.
