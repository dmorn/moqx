## What to build

Refactor the transport API and data structures so connection-scoped and
stream-scoped state can be owned independently while keeping
`MOQX.Transport` functional and process-free.

The clean target vocabulary is `MOQX.Transport.Conn` and
`MOQX.Transport.Conn.Stream`. Do not keep both `Transport.Conn` and
`Transport.Connection`; this library is pre-stable and backward compatibility
is not a constraint. `Conn.Stream` must represent bidirectional streams,
locally initiated unidirectional streams, and peer-initiated unidirectional
streams through stream info and side availability, not through separate stream
modules.

The refactor should make it possible for an OTP/GenStage layer above transport
to run one sender process per stream: each stream owner can hold stream-local
send state, submit async sends to the backend, receive its own
`send_complete` feedback, and use that feedback as backend-credit demand. The
transport layer must not implement the OTP process architecture itself; it must
provide functional primitives and data ownership boundaries that make that
architecture possible.

This is expected to change stream and mixed benchmark behavior. Existing #45
and #46 results remain evidence for the old single-pump/global-context shape,
but stream and mixed baselines must be refreshed after the refactor before
closing performance issues.

## Acceptance criteria

- [x] Rename the public connection handle/state vocabulary to
      `MOQX.Transport.Conn` and remove the confusing parallel
      `MOQX.Transport.Connection` name.
- [x] Move stream vocabulary under the connection namespace as
      `MOQX.Transport.Conn.Stream`, with stream info/send token modules nested
      or named consistently under that hierarchy.
- [x] Preserve a functional API style: calls receive explicit transport state
      and return updated state; no `Application` env, mutable globals, or OTP
      process ownership is introduced into the transport core.
- [x] Decompose broad context state so connection-scoped state and
      stream-scoped state can be owned by different logical callers without
      stale context copies or split-brain pending-send queues.
- [x] Keep `Conn.Stream` generic across bidirectional and unidirectional
      streams, using stream metadata and side availability to decide whether
      send, receive, FIN, RESET_STREAM, or STOP_SENDING operations are valid.
- [x] Make stream send-completion correlation stream-local. `send_complete`
      remains backend/buffer credit for an accepted send token, not peer
      delivery proof.
- [x] Keep DATAGRAM semantics admission-driven in the hot path. Do not reopen
      DATAGRAM send-state pacing unless a separate correctness or diagnostics
      issue requires it.
- [x] Update the support transport and quicer adapter contract tests so both
      implementations verify the new `Conn`/`Conn.Stream` ownership model.
- [x] Update protocol/session code and benchmark tooling in the same coherent
      migration so the repository is not left with mixed `Connection` and
      `Conn` APIs.
- [x] Update benchmark diagnostics or metadata enough to distinguish the
      sender topology used by stream and mixed runs, then rerun local
      calibration and record the need for fresh remote #45/#46 baselines.

## Notes

This issue is motivated by the #45 mixed stream/control evidence: the current
single-pump shape can turn independent QUIC streams into one BEAM-side
completion-credit loop. The new transport API should let benchmark and
production runners test a more natural process model without embedding that
runner model inside the transport abstraction.
