# Improve MOQX-client mixed stream/control pressure

Status: ready-for-agent
Type: AFK
Category: performance

## Parent

`.scratch/transport-layer-foundation/issues/26-harden-transport-pressure-abstractions.md`

## What to build

Diagnose and improve the remaining MOQX-client caller-side stream/control
pressure gap after the DATAGRAM path was reclassified as close enough.

The next v1 product target is caller-side MOQ behavior: connect out, publish or
subscribe over streams, and keep control traffic healthy while object-like
streams are under pressure. Listener/relay performance is explicitly out of
scope for the current harness, and QUIC DATAGRAM tuning should not be reopened
unless a concrete draft-14 interop bug appears.

The current x86-control evidence from run
`20260609T093717Z-issue40-x86-control-mixed-pressure-32x1000-1` shows a real
stream/control gap on a controlled path:

- workload: 32 object-like streams, 1000 x 1180-byte payloads per stream, and
  100 x 64-byte control messages at 100 messages/sec;
- reference `quicprobe -> quicprobe`: 116.99 Mbps, control p99 37.95 ms, no
  break symptom;
- `moqxprobe -> quicprobe`: 73.37 Mbps, control p99 139.43 ms, no break
  symptom;
- the old mailbox artifact is gone: final `message_queue_len=0`, peak 497,
  32,000 object send completions, 100 control send completions, and zero
  pending object/control completions.

This issue should make the mixed stream/control loop the new performance
progress tracker, equivalent to what #40 did for DATAGRAM.
