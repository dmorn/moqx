# Implement MOQ Lite 04 in the multi-protocol runtime

Status: needs-triage
Type: enhancement

## Parent

`.scratch/moq-lite-04-protocol/PRD.md`

## What to build

When this work is resumed, implement MOQ Lite draft-04 directly in the
architecture accepted by ADR-0010 before adding real-QUIC integration
coverage. The removed standalone implementation may be consulted through git
history, but it is not a compatibility boundary or migration substrate.

The implementation should preserve the protocol's wire and lifecycle behavior
while using the current ownership and entrypoints:

- MOQ Lite messages, codecs, state, commands, events, and errors move under
  `MOQX.Protocol.MOQLite04`;
- the implementation satisfies `MOQX.Protocol`;
- the common `MOQX.Runtime.ConnectionDriver` owns the transport context and
  applies returned transitions;
- the stable public API accepts endpoint plus `protocol: :moq_lite_04`;
- public subscribe intent uses `MOQX.TrackRef` and protocol-neutral operations;
- no protocol is inferred from the endpoint or ALPN;
- no `MOQX.MOQLite04` compatibility facade or parallel runtime is introduced.

This is a structural migration, not a request to make MOQ Lite behave like
draft-14. Its immediate-active lifecycle, transaction streams, group streams,
messages, and error semantics remain implementation-owned.

## Acceptance criteria

- [ ] `MOQX.Protocol.MOQLite04` implements every `MOQX.Protocol` callback.
- [ ] Its transport spec selects ALPN `moq-lite-04` and declares its required
      transport capabilities explicitly.
- [ ] Existing payload codec, stream codec, session, subscriber, publisher, and
      smoke behavior remains covered after namespacing changes.
- [ ] `MOQX.Runtime.ConnectionDriver` can connect and drive MOQ Lite through
      normalized transport events and returned transport actions.
- [ ] `MOQX.connect(endpoint, protocol: :moq_lite_04)` returns the stable public
      client shape.
- [ ] Public subscribe and delivery use protocol-neutral operations/events;
      MOQ Lite wire structs remain available only at the implementation layer
      or through a deliberate advanced API.
- [ ] No mutable `Application` environment is introduced.
- [ ] No hostname, URI, or ALPN inference selects the protocol.
- [ ] Default support-transport tests remain deterministic and hermetic.
- [ ] Documentation and examples use the explicit protocol-selection API.
- [ ] `mix format`, default tests, and `mix credo --strict` pass.
