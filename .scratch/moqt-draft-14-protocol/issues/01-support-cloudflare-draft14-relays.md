# Support Cloudflare draft-14 relays through an explicit protocol variant

Status: ready-for-agent
Type: enhancement

## Goal

Add the first MOQT draft-14 protocol implementation by proving a real subscriber
path against Cloudflare's public draft-14 relay and test stream.

The implementation must establish the multi-protocol architecture that future
variants can follow. `draft-14-cloudflare`, `draft-14-moqtail`, and
`moq-lite-04` may share transport and generic binary primitives, but each owns
its message model, framing/stream codecs, session lifecycle, commands, events,
and protocol errors.

The eventual public API must make protocol selection explicit at connection
time. A caller should supply the endpoint and desired protocol implementation;
the implementation must not infer a protocol from a hostname, silently fall
back between variants, or expose transport-profile selection as the user-facing
protocol API.

## First vertical slice

Start with the unauthenticated subscriber path against Cloudflare's public Big
Buck Bunny test stream:

- endpoint: `draft-14.cloudflare.mediaoverquic.com:443`;
- native QUIC ALPN: `moq-00`;
- MOQT version: draft-14, encoded as `0xff00000e`;
- namespace: `bbb`;
- catalog track: `.catalog`;
- packaging: CMSF/CMAF;
- advertised media: H.264, 1280x720;
- discovery: live `SUBSCRIBE`, not `FETCH`.

The integration test should connect with the public API, complete
CLIENT_SETUP/SERVER_SETUP, subscribe to `bbb/.catalog`, receive and decode a
catalog object, select an advertised media track, subscribe to it, and prove at
least one media object is delivered. Track selection should come from the
catalog rather than hard-coding an unverified media track name.

If the relay's catalog is temporarily unavailable, the test should fail with a
clear external-relay diagnostic. It must not turn a protocol failure into a
skip. The test may be separately selected from local real-QUIC tests so a
Cloudflare outage does not obscure repo-owned integration coverage.

## Public API and ownership constraints

Design the vertical slice so adding another protocol implementation does not
require conditionals throughout application code.

- The public connection shape is
  `MOQX.connect(endpoint, protocol: :cloudflare_draft_14)` or the equivalent
  explicit implementation-module form.
- `MOQX.Protocol.Resolver` maps built-in identifiers to implementation modules
  without inspecting the endpoint hostname.
- `MOQX.Runtime.ConnectionDriver` owns the transport context, selected protocol
  state, action application, event delivery, timeouts, and shutdown.
- `MOQX.Protocol.CloudflareDraft14` implements the `MOQX.Protocol` contract.
- Standard draft-14 message structs and codecs live under the reusable
  `MOQX.Protocol.MOQTDraft14` wire package.
- Endpoint parsing, protocol dispatch, and stable client-facing result/error
  shapes may be shared.
- The selected protocol owns its ALPN and transport capability requirements.
- The selected protocol owns setup and teardown, command validation, message
  structs, payload encoders/decoders, stream framing, per-stream decoder state,
  session lifecycle, protocol events, and error-code interpretation.
- Protocol sessions remain pure reducers. They consume normalized
  `MOQX.Transport` events or local commands and return updated state, protocol
  events, and transport actions as data.
- Runners apply transport actions through `MOQX.Transport`; protocol code must
  not match raw `:quicer` messages or call `quicer` directly.
- Transport stream identity is preserved. Bytes from independent streams are
  never combined before protocol decoding.
- `MOQX.Codec` remains limited to genuinely protocol-neutral binary helpers and
  encoder/decoder contracts. Cloudflare or draft-14 message tables and framing
  do not belong there.
- The shared `MOQX.Protocol` behaviour standardizes only the driver transition
  boundary. It does not define a common Session struct or lifecycle. Do not
  force draft-14 into MOQ Lite's transaction-stream model.
- Protocol implementation selection is not mutable global configuration and
  must not use `Application` environment as a seam.
- Do not select a protocol implicitly from the endpoint hostname. Endpoint
  presets may be optional conveniences, but the resolved protocol choice must
  remain explicit and inspectable.

ADR-0010 and the protocol scaffold define this ownership model. The first
vertical slice should make the scaffold executable rather than introducing a
second connection path.

## Cloudflare deployed protocol surface

Cloudflare documents a subset of IETF MOQT draft-14 rather than a private wire
format.

Supported draft-14 control messages:

- CLIENT_SETUP and SERVER_SETUP;
- SUBSCRIBE, SUBSCRIBE_OK, SUBSCRIBE_ERROR, and UNSUBSCRIBE;
- TRACK_STATUS and TRACK_STATUS_OK;
- PUBLISH_NAMESPACE, PUBLISH_NAMESPACE_OK, PUBLISH_NAMESPACE_ERROR,
  PUBLISH_NAMESPACE_CANCEL, and PUBLISH_NAMESPACE_DONE;
- PUBLISH_OK and PUBLISH_DONE.

Explicitly unsupported in the managed relay:

- GOAWAY;
- MAX_REQUEST_ID and REQUESTS_BLOCKED messages;
- SUBSCRIBE_UPDATE;
- PUBLISH_ERROR;
- FETCH, FETCH_OK, FETCH_ERROR, and FETCH_CANCEL;
- TRACK_STATUS_ERROR;
- SUBSCRIBE_NAMESPACE, SUBSCRIBE_NAMESPACE_OK, SUBSCRIBE_NAMESPACE_ERROR, and
  UNSUBSCRIBE_NAMESPACE.

The first slice must not send unsupported messages. In particular, catalog
discovery uses a live subscription to `.catalog`. Support for the setup
`MaxRequestId` parameter in public `moq-rs` must not be confused with support
for the unsupported MAX_REQUEST_ID control message.

The console identifies draft-14 as the recommended endpoint and draft-07 as
deprecated. Cloudflare's general MoQ overview has lagged behind the product
console; use the dated feature matrix and deployed behavior as the current
contract.

## Cloudflare public implementation findings

The only public Cloudflare data-plane implementation found is `cloudflare/moq-rs`.
Its `draft-ietf-moq-transport-14` branch is the relevant reference; `main` has
since advanced to a newer draft. It is strong implementation and interop
evidence, but it is not proof that the managed service runs the exact same
binary or exposes every open-source feature.

Relevant behavior in that branch:

- raw QUIC uses ALPN `moq-00`;
- WebTransport uses HTTP/3 ALPN `h3`;
- the current project slice remains native-QUIC-only per `CONTEXT.md`;
- the first client-initiated bidirectional stream is the control stream;
- `Session::connect` offers draft-14 and performs CLIENT_SETUP/SERVER_SETUP;
- raw QUIC carries the logical relay path in the CLIENT_SETUP `PATH` parameter;
- WebTransport carries the path in the extended CONNECT request;
- both subgroup streams and object datagrams are implemented;
- path values are bounded and normalized: they start with `/`, reject empty or
  dot segments and percent encoding, and trim a trailing slash;
- setup parameter identifiers include `Path = 0x1`, `MaxRequestId = 0x2`,
  `AuthorizationToken = 0x3`, `MaxAuthTokenCacheSize = 0x4`, `Authority = 0x5`,
  and `MOQTImplementation = 0x7`;
- the public relay coordinator models read/write versus read-only scope
  permissions, origin fallback, and lingering subscriptions;
- the draft-14 branch declares the authorization-token setup parameter, but no
  managed-relay token wiring was found in the public session/relay path.

Cloudflare also publishes a draft-14 interoperability client with cases for:

- setup only;
- namespace publication only;
- subscribe error;
- publish then subscribe;
- subscribe before publish;
- PUBLISH_NAMESPACE_DONE.

Its test namespace is `moq-test/interop`, its track is `test-track`, and its
setup timeout is 10 seconds. These scenarios are useful references for later
publisher and lifecycle coverage, but the first implementation slice is the
public `bbb` subscriber test.

## Managed relay control plane

Cloudflare exposes account-level relay CRUD APIs:

- `POST /accounts/{account_id}/moq/relays`;
- list/get/update/delete endpoints;
- token rotation for either publish+subscribe or subscribe-only credentials.

Creating a relay returns two generated token values, shown once:

- `token_publish_subscribe`: publish and subscribe permission;
- `token_subscribe`: subscribe-only permission.

The API examples show JWT-shaped Ed25519 tokens. Do not depend on the example's
serialization without inspecting a real relay credential and documentation.
Token rotation immediately invalidates the previous token according to the
Cloudflare SDK.

Managed relay configuration includes:

- lingering subscribe, enabled by default with a 30 second relay-level ceiling
  and a documented maximum of 300 seconds;
- origin fallback, an ordered set of upstream MOQT relay URLs used when a local
  publisher is absent;
- a constraint that lingering subscribe and origin fallback are mutually
  exclusive.

Cloudflare's current API uses `origin_fallback`/`origins`; older generated
surfaces referred to `upstreams`. Treat the live API schema as authoritative
when managed-relay work begins.

Managed authentication remains an open question. Determine whether tokens are
carried in the draft-14 authorization setup parameter, the WebTransport
request, a URL component, or another Cloudflare-specific mechanism. Do not
assume the pre-redesign `moqx` `?jwt=` convention applies to Cloudflare.

If account credentials are needed for a later managed-relay slice, retrieve
them through the configured 1Password integration and keep token values out of
test output, fixtures, issue comments, and git.

## Existing `moqx` history

Pre-redesign `moqx` version `v0.7.1` contained a
`cloudflare-draft14-bbb` inspection preset:

- URL `https://draft-14.cloudflare.mediaoverquic.com`;
- namespace `bbb`;
- catalog track `.catalog`;
- `skip_fetch?: true`;
- note: "Cloudflare moq-rs style relay; uses .catalog and typically requires
  live subscribe."

The old inspector attempted `catalog` and then `.catalog`, and fell back from
FETCH to repeated live subscriptions when the relay returned no objects, an
unknown track, or a timeout. The README also documented publisher/subscriber
roundtrip commands against both the public draft-14 endpoint and
`interop-relay.cloudflare.mediaoverquic.com`.

This history is useful behavioral evidence, but no retained test output was
found proving those commands passed. The old implementation targeted a
WebTransport-oriented API and should be treated as interop/reference material,
not restored as the new architecture.

## Evidence collected during triage

- `draft-14.cloudflare.mediaoverquic.com:443` completed a direct QUIC/TLS
  handshake with ALPN `moq-00`; the server then closed a deliberately malformed
  application stream with EOF.
- HTTPS GET to the endpoint returned Cloudflare HTTP 403, which is expected for
  a guarded data-plane front door and is not a MOQT failure.
- The authenticated Cloudflare console showed the draft-14 endpoint, the `bbb`
  test stream, CMSF/H.264 metadata, and the same supported-message matrix as the
  public feature-matrix page.
- A full Cloudflare reference-client setup exchange has not yet been captured.
  The attempted local build required downloading third-party Rust dependencies,
  so it was not executed as part of read-only triage.

## Acceptance criteria

- [ ] The implementation follows ADR-0010 and makes the existing
      `MOQX.Protocol`, resolver, transition, transport-spec, and connection
      driver scaffold executable for Cloudflare.
- [ ] A caller selects the Cloudflare draft-14 implementation explicitly while
      supplying the relay endpoint; hostname inference and silent protocol
      fallback are absent.
- [ ] Cloudflare draft-14 message structs, payload codecs, stream codecs,
      session state, commands, events, and protocol errors live under a
      variant-owned namespace.
- [ ] Shared code added under `MOQX.Codec` is demonstrably protocol-neutral.
- [ ] The protocol Session is a pure reducer over normalized transport events
      and local commands and returns transport actions as data.
- [ ] Native QUIC connects using ALPN `moq-00`, negotiates version
      `0xff00000e`, and completes the draft-14 setup exchange.
- [ ] The initial client supports the minimum Cloudflare subscriber control
      path: SUBSCRIBE, SUBSCRIBE_OK, SUBSCRIBE_ERROR, and UNSUBSCRIBE.
- [ ] The initial client decodes the object-delivery forms actually observed on
      the Cloudflare test stream, preserving stream identity and object
      metadata. Subgroup and datagram paths are implemented or the unobserved
      path is recorded as a scoped follow-up with captured evidence.
- [ ] An ExUnit test tagged `:integration` connects to Cloudflare's public
      endpoint, subscribes live to `bbb/.catalog`, and decodes a catalog object.
- [ ] The integration test chooses an advertised media track from that catalog,
      subscribes to it, and proves at least one media object is received.
- [ ] The external test has bounded setup/subscription/object timeouts and
      actionable failure diagnostics without printing secrets.
- [ ] The Cloudflare external test is excluded from default `mix test` and can
      be selected independently from repo-owned real-QUIC integration tests.
- [ ] Default tests remain fast and hermetic, with support-transport contract
      and reducer tests covering framing fragmentation, invalid ordering,
      unsupported messages, peer FIN/reset, and connection shutdown.
- [ ] Public documentation identifies the supported Cloudflare message subset,
      the explicit protocol-selection API, the public test endpoint, and the
      difference between external smoke evidence and local deterministic tests.
- [ ] `mix format`, default tests, the targeted Cloudflare integration test,
      and `mix credo --strict` pass before completion.
